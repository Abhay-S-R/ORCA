## 1. Overall / Cross-Cutting Features

These work for **every persona**, all the time.

| Feature | What it does |
|---|---|
| **Conversational AI** | Ask in any Indian language; ORCA understands and replies in the same language. Handles follow-ups, typos, slang, mixed text. |
| **Deterministic Safety Core** | GO / CAUTION / NO-GO verdicts are computed by explicit threshold arithmetic — never generated by an LLM. |
| **Offline-tolerant LLM chain** | Tries Gemini then Groq then local Ollama. If all fail, still returns a verdict, citations and map. |
| **Evidence-cited answers** | Every claim carries its source dataset, acquisition timestamp and confidence tier (HIGH / MEDIUM / LOW-DATA). |
| **Persona-aware rendering** | Same computed facts, different presentation depth and vocabulary for each of the four personas. |
| **Query cache & coalescing** | Identical queries within the same window share one upstream run (Redis, 30-min TTL). |
| **Priority lane** | Safety-check queries run in a dedicated semaphore pool so demand spikes can not starve them. |
| **Data freshness labelling** | Stale data is dated and labelled; never presented as current. |
| **Fail-safe degradation** | A broken data feed produces a LOW-DATA labelled answer, not a 500 error. |
| **Critic agent** | A judge model checks every narrative against measured facts and may request one revision. Cannot alter the verdict. |
| **Feedback** | Users can rate any response (thumbs up / down). |
| **i18n (10 languages)** | All UI strings translated in en, hi, ta, te, ml, kn, bn, mr, gu, or. A CI checker keeps dictionaries in step. |
| **JWT auth with refresh tokens** | Secure sign-in, sign-out, refresh-token rotation. |

## 9. Persona Answer Matrix — Same Answer, Different Views

The **same computed facts** are rendered differently per persona when an answer arrives:

| Persona | What they see |
|---|---|
| **Fisherman** | Large GO/CAUTION/NO-GO banner + "Why this answer?" plain-language explanation |
| **Commercial Navigator** | Structured readout grid: wave height vs limit, wind speed vs limit, tide window, bathymetry hazards |
| **Researcher** | Full statistical summary with sensor metadata + CSV/JSON export button |
| **Coastal Authority** | Threat-level classification + CAP-shaped preview snippet |

- Safety Assessment, Fishing Zone Advisory, Maritime Boundary Standoff, Surface Current Outlook, Wave & Swell Outlook, Wind Speed & Direction, Tide/Weather/Sea Conditions, Marine Conditions Summary.

## 10. Agent Pipeline

Runs on every query. 15 LangGraph nodes.

| Agent | What it does | LLM? |
|---|---|---|
| `distress_check` | Phrase-list SOS detection in 7 languages + MRCC lookup | Escalate-only |
| `language_ingress` | Detects script; translates native-script to English | No (Bhashini / IndicTrans2) |
| `planning` | Reads message, validates place + date, builds execution plan | One call |
| `out_of_scope` | Greetings, clock, inland places, capability questions, follow-ups | Writes reply from fixed facts |
| `marine_data_discovery` | Ranks sources by authority + freshness; walks fallback cascades | No |
| `weather_intelligence` | Waves, wind, lightning, cyclone, IMD hazard alerts | No |
| `geospatial` | IMBL and MPA distances, bathymetry, fishing ban, nearest PFZ | No |
| `ocean_analytics` | Tides, PFZ persistence, sector status, catch analysis | No |
| `risk_assessment` | Deterministic GO / CAUTION / NO-GO verdict | No |
| `visualization` | Map layers and chart specs, geometry validated | No |
| `reporting` | Writes narrative around the facts with citations | Yes |
| `critic` | Fact-checks narrative; one revision allowed. Cannot change verdict | Yes |
| `language_egress` | Translates reply back; masks numbers and verdict words | No (Bhashini / IndicTrans2) |

**Design rule:** Agents that decide whether a boat leaves port never call a language model.
