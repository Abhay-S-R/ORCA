## Overview

ORCA sits on top of India's fragmented marine data ecosystem (INCOIS, MOSDAC, IMD, Bhuvan, Copernicus, NASA and others). It turns a fisherman's question into one synthesized, evidence-backed answer in their own language, with a map and a clear verdict.

**Coverage, stated exactly.** ORCA performs national place resolution and uses national PFZ sectors, with deep validation in the Gulf of Mannar pilot. A question naming Veraval, Kakinada, Paradip, Digha, Port Blair or Kavaratti resolves to that place, on that coast, in its own INCOIS sector; it is not answered with Tamil Nadu's numbers. The pilot region adds depth, not reach: surveyed positions, a hand-checked MPA polygon, a tide-gauge station and published catch validation, none of which exist yet for every coast. Where a position or a sector is a fallback rather than the one the user asked about, ORCA says so on the card before it answers.

**Safety decisions are never generated by a language model.** Go/no-go verdicts, geofence breaches and hazard tiers are computed by deterministic Python against documented thresholds. A language model reads the question and writes the explanation; it cannot change a verdict, invent a place, a date or a value.

## Design principles

ORCA's founding principle is:

> **Talk like a chatbot, stay accurate like an instrument.**

- **Talk like a chatbot.** A language model reads every message and writes every reply. It handles typos, plurals, shortenings, slang, mixed-language text and follow-ups using the conversation history, and answers small talk and off-topic messages naturally, in the user's language. Hand-written word lists are a fast path or the offline fallback; they never have the final say.
- **Stay accurate like an instrument.** Facts, numbers and the go/no-go verdict come from the agents, the data and deterministic code, never from the model. What the model extracts from a message (a place, a date, an intent) is validated against real data (the gazetteer, the forecast horizon, the routing table) before anything acts on it.

Supporting rules that every agent and API response is checked against:

| # | Principle |
|---|---|
| 1 | **The nodes that decide whether a boat leaves port are deterministic.** Weather, geospatial and risk assessment never call a model. |
| 2 | **Intent decides what fires. Persona decides how it is said.** Planning is persona-blind; only reporting reads persona. |
| 3 | **Every claim is provenance-stamped.** Source dataset, acquisition timestamp and a confidence tier travel with every fact. |
| 4 | **Uncertainty defaults to the safety-conservative rendering.** Missing or low-confidence data produces a cautious answer, never a confident guess. |
| 5 | **Quality validation runs regardless of persona.** Every query passes through the Critic. |
| 6 | **Monitoring does not wait for a query.** The Sentinel agent runs continuously. |
| 7 | **Every emergency signal has one owner, and it is never the model alone.** Distress detection is phrase-list matching; a model check may raise an alarm but can never clear one. |
| 8 | **The model is optional.** Any answer can be re-run with every language model disabled; the verdict, thresholds, geofences, citations and confidence remain, and only the prose degrades to a plain statement of the measured facts. |
| 9 | **Optimizations never trade against principles 1, 4 or 6.** |

## The agent pipeline

Every query flows through a compiled LangGraph `StateGraph` (`backend/orca/graph/graph.py`) of fifteen nodes.

```
                      USER QUERY
                          |
                          v
                 Distress Check  ---- distress ----> MRCC handoff --> END
                          |
                          v
                 Language Ingress
        (native script to English: Bhashini, IndicTrans2 fallback)
                          |
                          v
                      Planning
   one model reading: kind, intent, places, time, agents
   validated in code against the gazetteer and the 7-day horizon
                          |
        +-----------------+---------------------+
        | refusal, chat, greeting,                | sea question
        | inland place, off-topic                 v
        v                              Marine Data Discovery
   Out-of-scope reply                  (ranked source selection)
        |                                         |
        v                  +----------------------+----------------------+
       END                 v                      v                      v
                   Weather Intelligence       Geospatial          Ocean Analytics
                           |                      |                      |
                           +----------+-----------+----------+-----------+
                                      v                      v
                              Risk Assessment          Visualization
                          (deterministic verdict)     (map layers, charts)
                                      +----------+-----------+
                                                 v
                                             Reporting
                                    (narrative around the facts)
                                                 |
                                                 v
                                              Critic
                                  (fact-check, one revision at most)
                                                 |
                                                 v
                                          Language Egress
                                                 |
                                                 v
                                           USER RESPONSE
```

Which agents run for a sea question is planned per query: the planner proposes the set, and code enforces the invariants. The agents that produce the verdict inputs (weather, geospatial, risk assessment), reporting and the critic always run; the agents a question's intent names always run; the model may add others. Order is fixed by code, never by the model.

| Node | Role | Uses a language model |
|---|---|---|
| `distress_check` | Phrase-list distress detection, MRCC lookup, handoff | Escalate-only check |
| `language_ingress` | Script detection; native-script text to English | No (Bhashini, IndicTrans2) |
| `planning` | Reads the message, validates places and dates, builds the execution plan | One call; deterministic fallback offline |
| `out_of_scope` | Replies to greetings, the clock, capability questions, follow-ups about ORCA, inland places and off-topic messages | Writes the reply from fixed facts |
| `marine_data_discovery` | Ranks and selects data sources, with fallback cascades | No |
| `weather_intelligence` | Waves, wind, lightning, cyclone and IMD alerts | No |
| `geospatial` | IMBL and MPA distances, bathymetry, fishing-ban order, nearest PFZ | No |
| `ocean_analytics` | Tides, PFZ persistence, sector status, catch analysis | No |
| `risk_assessment` | GO / CAUTION / NO-GO verdict | No |
| `visualization` | Map layers and chart specifications, geometry validated | No |
| `reporting` | Writes the answer around the computed facts, with citations | Yes |
| `critic` | Judges the narrative against the facts | Yes |
| `critic_cancelled`, `critic_reinvoke` | Re-invocation budget handling | No |
| `language_egress` | Translates the reply back; masks numbers and verdict words | No (Bhashini, IndicTrans2) |

**Running continuously in the background:** the **Sentinel** agent polls every registered watch location and dispatches a notification when conditions cross a threshold (GO to CAUTION to NO-GO). A Postgres advisory lock ensures only one process fires notifications in a multi-instance deployment.

## How a message is understood

Planning makes one model call that reads the message together with the last few turns of the conversation, the caller's position and the current time. It returns a structured reading, and code then validates it against real data.

| Kind | Handled as |
|---|---|
| Sea question | Validated, then routed to the specialist agents |
| Greeting or small talk | Short model-written reply |
| Clock or position | Answered from the server clock and the caller's actual position |
| Capability question | Model-written description of what ORCA can and cannot do |
| Follow-up about ORCA's last reply | Model-written reply in context; no sea agents run |
| Inland place (for example, weather in Bengaluru) | Plain statement that ORCA covers the sea; no sea agents run |
| Reset or language switch | Applied and confirmed |
| Distress | Handled by the distress path before planning |
| Off-topic | Polite redirect |

**Validation before anything acts on the reading:**

- A place must resolve in the gazetteer or be a whole coastline. An unknown place produces a "which place do you mean?" question, never a silent default. A place the model calls inland is overruled if the gazetteer knows it as coastal.
- A time must fall inside the forecast horizon (seven days). A date in the past or beyond the horizon is refused with the range ORCA can answer.
- Intents must be rows of the routing table, and agent names must be real graph nodes.
- An explicit position outside the data extent, or on land, is refused.

If no language model is reachable, planning falls back to the deterministic routing tiers, so the system still answers.

## Architecture

### Backend: FastAPI and LangGraph

The backend (`backend/orca/api/main.py`) is a FastAPI application on Python 3.11. Its primary interface is a streaming Server-Sent Events endpoint (`GET /query`) that emits one `agent_span` frame per agent as it completes, followed by a single `final_response` frame containing the answer, verdict, map layers, citations and audit trace.

- **Priority lane.** Safety-check queries run in a dedicated semaphore pool, so a demand spike cannot starve the highest-stakes questions.
- **Query cache and coalescing.** Identical queries in the same window are folded into one upstream run. Answers are cached in Redis for 30 minutes, the ceiling set by the fastest-changing safety source (lightning), and a "try again" request bypasses the cache.
- **Language-model chain.** Each tier (cheap, mid, reasoning) is an ordered list of providers: Gemini, then Groq, then a local Ollama model. A failing provider is skipped for a short cooldown, and the number of calls reported counts answers, not failed attempts.
- **Sentinel loop.** Started from the FastAPI lifespan; guarded by a Postgres advisory lock.
- **Fail-safe degradation.** Every node is wrapped so an exception degrades that node to an empty, labelled output instead of aborting the pipeline. A broken weather feed produces a LOW-DATA answer, not a 500.
- **Data freshness.** Every dataset is classified by how fast it must be refreshed, and answers state the age of what they cite. See `docs/data/ORCA_Data_Freshness_Contract.md`.

### Frontend: Next.js and MapLibre GL

A Next.js 16 / React 19 application that renders the agent trace and the final answer progressively as SSE frames arrive. Maps use MapLibre GL with deck.gl overlays. The interface is translated into ten languages, and a checker (`npm run check:i18n`) keeps every dictionary in step with English.

### Data layer

| Service | Purpose |
|---|---|
| **PostgreSQL 16 with PostGIS** | Accounts, vessel profiles, saved locations, chat history, audit traces, watch subscriptions, notifications, distress events |
| **Redis 7** | Query cache, request coalescing, session context |
| **`data/` directory** | Local datasets (PFZ advisories, forecasts, bathymetry, boundaries, tide tables). Not stored in git; refreshed by scripts |

Database migrations live in `infra/db/`.

## API reference

### `GET /query`

Runs the full pipeline and responds as `text/event-stream`.

| Parameter | Type | Description |
|---|---|---|
| `q` | string | The user's message, in any supported language |
| `lat`, `lon` | float | Caller's coordinates; if absent, the place is resolved from the text |
| `persona` | string | `fisherman`, `commercial_navigator`, `researcher`, `coastal_authority` |
| `depth` | string | `SHALLOW`, `STANDARD` or `DEEP` |
| `vessel_class` | string | `small_fishing`, `mechanized_trawler`, `cargo_vessel` |
| `distress` | bool | Activates the SOS path directly |
| `session_id` | string | Ties the message to a conversation, enabling follow-ups |
| `llm` | string | `off` re-runs the question with every language model disabled |
| `fresh` | bool | Bypasses the query cache and the conversation window |
| `drop` | string | Comma-separated values not to inherit from the chat: `place`, `vessel_class`, `intent` |

**Event types**

```jsonc
// agent_span: one per agent as it finishes
{
  "type": "agent_span",
  "agent_name": "weather_intelligence",
  "status": "ok",
  "confidence_tier": "HIGH",
  "latency_ms": 312,
  "reasoning_summary": "Wave height 1.4 m, within safe limits"
}

// final_response: one at the end
{
  "type": "final_response",
  "final_english_response": "...",
  "final_vernacular_response": "...",     // in the user's language
  "risk_assessment": { "go_no_go": "GO" },
  "confidence_tier": "HIGH",
  "lead_with_verdict": true,              // false when a GO answers a non-safety question
  "citations": [...],
  "visualization_payload": { "map_layers": [...], "chart_specs": [...] },
  "skipped_agents": [...],
  "llm_call_count": 4
}
```

## Getting started

**Prerequisites:** Python 3.11, Node.js, and Docker (for PostgreSQL and Redis).

```bash
# 1. Configuration
cp .env.example .env            # add the keys you have; the file comments say what each enables

# 2. Database and cache
docker compose up -d            # PostGIS 16 and Redis 7

# 3. Backend
cd backend
python -m venv .venv            # activate it, then:
pip install -r requirements.txt
uvicorn orca.api.main:app --port 8000

# 4. Frontend (in a second terminal)
cd frontend
npm ci
npm run dev                     # http://localhost:3000
```

**Datasets.** The `data/` directory is not stored in git. Refresh it with the scripts in `scripts/` (`scripts/refresh_all.py`, plus the daily and weekly wrappers in `scripts/cron/`). See `docs/guides/ORCA_Data_Refresh_Guide.md` and `docs/guides/ORCA_Data_Refresh_Cron_Guide.md`.

**Language models.** Set `GEMINI_API_KEY` and/or `GROQ_API_KEY`. With no key, ORCA runs in its deterministic mode: verdicts, citations and maps are unchanged and the prose is a plain statement of the measured facts. `ORCA_LLM_ENABLED=0` forces this mode.

**Local models (optional).** `backend/scripts/download_ml_models.py` fetches the IndicTrans2, Whisper and MMS-TTS weights. `ORCA_LOCAL_MODELS=0` skips loading them on small hosts.

**Translation and speech.** Add the three `BHASHINI_*` credentials to use Bhashini. Without them ORCA falls back to the local models.

## Pilot region

**Pilot is not the same as coverage.** Place resolution and PFZ sectors are national: every coastal state and both island territories resolve to their own positions and their own INCOIS sector. This section describes where ORCA has been validated deeply, which is a narrower claim.

The pilot region is the **South Tamil Nadu coast**: Thoothukudi, Rameswaram, Kanyakumari, Palk Bay and the Gulf of Mannar. It is the one region where every stakeholder group named in the problem statement has a current, non-hypothetical reason to use the platform:

- **Fishermen.** Documented consequences of accidental IMBL crossings in the Palk Strait, as recently as 2026.
- **Researchers.** Published validation: 44.9% of PFZ hits cluster on the Thoothukudi mid-shelf, driven by Thamirabarani river discharge, which gives the Ocean Analytics agent citable ground truth.
- **Coastal authorities.** North-east monsoon cyclone exposure makes hazard alerting a real requirement.
- **Maritime operators.** Route planning has genuine multi-layer constraints: the IMBL, the Gulf of Mannar Marine National Park and GEBCO depth contours.
- **ISRO and INCOIS reviewers.** Two active INCOIS sectors (North and South Tamil Nadu) allow sector-boundary handling to be demonstrated with real data.

**Cyclone seasonality.** For demonstrations outside October to December, Cyclone Gaja replay mode reproduces its landfall on the South Tamil Nadu coast from authentic IMD and MOSDAC data.

The IMBL boundary feature is a fisherman-safety navigation aid ("alert me before I approach the line"), never commentary on the India-Sri Lanka dispute.
